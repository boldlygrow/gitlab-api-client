# 5.0

* **Release Date:** 2026-09-07

## Overview

This release moves the project to the maintainer's `BoldlyGrow` namespace, replaces the deprecated `provisionesta/audit` dependency with `boldlygrow/audit-log`, extends framework support to Laravel v13, drops support for the legacy Laravel v8, v9, and v10 releases, and improves the error messages on thrown exceptions. The API surface, authentication, request data log filtering, exception classes, and response formatting are unchanged, so existing calls continue to work after the namespace and dependency updates below.

### New Features

- Add Laravel v13.x support
- Add [Laravel Pint](https://laravel.com/docs/pint) and [Pest](https://pestphp.com/) as development dependencies for linting and testing
- Add docblocks to the published config file documenting each configuration key
- Add the reason for a failed request to every exception message and to the audit log `errors` array

### What's Changed

- **Package Architecture**
    - The Composer package has been renamed from `provisionesta/gitlab-api-client` to `boldlygrow/gitlab-api-client`.
        - **Why:** The project is consolidating under the maintainer's `BoldlyGrow` organization alongside the related audit and actions packages.
    - The PHP namespace changed from `Provisionesta\Gitlab` to `BoldlyGrow\Gitlab`.
    - The `glamstack/gitlab-sdk`, `gitlab-it/gitlab-sdk`, and `provisionesta/gitlab-api-client` package names are retained as `replace` aliases for a smoother upgrade.
    - The `provisionesta/gitlab-laravel-actions` suggestion and README references were removed.
- **Error Handling**
    - Exception messages now include the reason that the GitLab API returned for the failure.
        - **Why:** Only the `message` key of the response body was checked. The GitLab API returns parameter validation failures under `error` (ex. `{"error":"ref is missing"}`) and OAuth failures under `error_description`, so the reason for most `400` responses was silently discarded and the exception showed only the method, status code, and URL.
    - The `error_description`, `error`, and `message` keys are now checked in order, and the first one present is used. A `message` containing validation errors keyed by attribute name is flattened to a single line (ex. `name: has already been taken, path: can't be blank`). If none of these keys are present, the response body is appended (truncated to 1000 characters) instead of being discarded.
    - The `503` and `5xx` Cloudflare exceptions now use the same message format. `ServiceUnavailableException` was previously thrown with no message at all, and the Cloudflare exceptions were thrown with a `json_encode()` of the response body, which produced the string `null` for the HTML error pages that Cloudflare actually returns.
    - The audit log `errors` array for an unsuccessful request now contains the same parsed reason.
    - **No action is required.** The exception classes, status code mapping, and `GITLAB_API_EXCEPTIONS` behavior are unchanged. Only the message text on the exception is different, so any code that matches on the exception class continues to work. Code that parses the exception message string should be reviewed.
- **Audit Logging**
    - The audit logging dependency changed from `provisionesta/audit` to `boldlygrow/audit-log`.
        - **Why:** `provisionesta/audit` is deprecated. `boldlygrow/audit-log` is its direct replacement under the maintainer's organization.
    - The imported class changed from `Provisionesta\Audit\Log` to `BoldlyGrow\AuditLog\AuditLog`, and log calls changed from `Log::create()` to `AuditLog::create()`. Event type strings and log levels are unchanged.
- **Framework Support**
    - Added Laravel v13.x support.
    - Removed support for the legacy Laravel v8, v9, and v10 releases.
        - **Why:** These versions are past their maintenance windows. Dropping them keeps the dependency matrix focused on supported framework releases.
    - The minimum PHP version is now `^8.2`. The supported Laravel range is `^11.0`, `^12.0`, and `^13.0`.
    - `nesbot/carbon` supports `^2.72.2 || ^3.0`.

### Upgrade Steps

- Update `composer.json` to require `boldlygrow/gitlab-api-client:^5.0` and run `composer update`.
- Perform a find and replace across your code base from `Provisionesta\Gitlab` to `BoldlyGrow\Gitlab`.
- If you reference the audit logger directly, update `Provisionesta\Audit\Log` to `BoldlyGrow\AuditLog\AuditLog` (and `Log::create()` to `AuditLog::create()`).
- Ensure your application is running Laravel v11, v12, or v13 and PHP v8.2 or newer before upgrading. Applications on Laravel v8, v9, or v10 must upgrade the framework first, or stay on `provisionesta/gitlab-api-client:^4.0`.
- Re-publish or update the config file to pick up the new docblocks if desired: `php artisan vendor:publish --tag=gitlab-api-client`.
- No functional change is required beyond the namespace and dependency updates. Your existing connection configuration, tokens, and API calls continue to work.
- This is not an exhaustive list. Review the `README.md` for the latest syntax and usage guidelines.
